Types of Data Structures • Stack : Definition, Representation, Operations, Implementation & Applications (Polish Notation, Postfix Evaluation)

What is a Data Structure?

A Data Structure is a group of data elements which provides an efficient way of storing and organizing data in the computer so that it can be used efficiently.

Examples: Array, Linked List, Stack, Queue, Tree, Graph. Used everywhere — Operating Systems, Compilers, AI, Graphics.

Classification of Data Structures

Data structures are classified in three ways. First see the full hierarchy (Primitive → Non-Primitive → Linear / Non-Linear → Static / Dynamic), then the three short views below.

By nature (Primitive / Non-Primitive) By arrangement (Linear / Non-Linear) By memory (Static / Dynamic)
Note: Stack and Queue can be implemented both ways — array = static, linked list = dynamic. In the tree above they are shown under Dynamic as a common classroom example.

Way 1 By Nature

  • Primitive — int, float, char, boolean, pointer
  • Non-Primitive — Array, List, Stack, Queue, Tree, Graph

Way 2 By Arrangement

  • Linear — Array, Linked List, Stack, Queue
  • Non-Linear — Tree, Graph, Heap, Dictionary

Way 3 By Memory

  • Static — Array (size fixed at compile time)
  • Dynamic — Linked List, dynamic Stack / Queue
Memory trick: Primitive = language ready-made. Non-Primitive = we build using primitives. Linear = one sequence. Non-Linear = hierarchy / network. Static = fixed size. Dynamic = grow / shrink at run time.

Stack — Definition

A Stack is a linear data structure in which elements may be inserted or deleted only at one end, called the TOP of the stack.

Stack follows the LIFO principle — Last In, First Out. The element inserted last is deleted first.

Real-life examples: pile of plates 🍽, stack of books 📚, deck of cards 🃏, bangles on a wrist, undo history in an editor.

Representation of Stack

A stack can be represented (implemented) in two ways:

1. Using Array (Static)

  • Fixed capacity called size (e.g. 6 elements).
  • A variable top keeps the index of the topmost element. Initially top = -1 (empty).
  • Adding beyond max size → Stack Overflow
  • Removing from an empty stack → Stack Underflow

2. Using Linked List (Dynamic)

  • Each element is a node (data + pointer to next node).
  • The head of the list acts as the top of the stack.
  • No fixed size — grows and shrinks at run time.
  • Overflow only when system memory is full.

Applications of Stack

  • Expression Conversion — Infix ↔ Postfix ↔ Prefix (Polish notations).
  • Expression Evaluation — evaluating postfix / prefix expressions.
  • Recursive function calls — the system keeps return addresses on a stack. Function called last returns first (LIFO).
  • Reversing data — reverse a string / number, decimal to binary conversion.
  • Balanced parentheses checking — compilers use a stack to match ( ), { }, [ ].
  • Undo / Redo, browser back button, backtracking.
Polish Notations: Prefix notation (+AB) is called Polish notation and Postfix notation (AB+) is called Reverse Polish notation. Named after Polish mathematician Jan Łukasiewicz.

Stack Implementation using Array (C — menu driven)

stack_array.c
#include <stdio.h>
#define MAX 100

int stack[MAX];
int top = -1;
int n;                       /* size of the stack */

void push()
{
    int val;
    if (top == n - 1)
        printf("\nStack Overflow\n");
    else
    {
        printf("Enter the value: ");
        scanf("%d", &val);
        top = top + 1;
        stack[top] = val;
    }
}

void pop()
{
    if (top == -1)
        printf("\nStack Underflow\n");
    else
    {
        printf("Deleted element: %d\n", stack[top]);
        top = top - 1;
    }
}

void display()
{
    int i;
    if (top == -1)
        printf("\nStack is empty\n");
    else
    {
        printf("Stack elements are:\n");
        for (i = top; i >= 0; i--)
            printf(" %d\n", stack[i]);
    }
}

int main()
{
    int choice = 0;
    printf("Enter the number of elements in the stack: ");
    scanf("%d", &n);
    printf("*** Stack operations using array ***\n");
    while (choice != 4)
    {
        printf("\n1.Push\n2.Pop\n3.Show\n4.Exit\n");
        printf("Enter your choice: ");
        scanf("%d", &choice);
        switch (choice)
        {
            case 1: push();    break;
            case 2: pop();     break;
            case 3: display(); break;
            case 4: printf("Exiting....\n"); break;
            default: printf("Please enter a valid choice\n");
        }
    }
    return 0;
}
Sample Output: Push 12 → Show prints 12 → Push 25 → Show prints 25 12 (top printed first) → Exit.

Stack Implementation using Linked List (C)

Here the head node is the top. Push = insert at beginning, Pop = delete from beginning. No fixed size!

stack_linkedlist.c
#include <stdio.h>
#include <stdlib.h>

struct node
{
    int data;
    struct node *next;
};
struct node *top = NULL;     /* top of the stack */

void push(int val)
{
    struct node *newnode = (struct node*)malloc(sizeof(struct node));
    if (newnode == NULL)
    {
        printf("Stack Overflow (no memory)\n");
        return;
    }
    newnode->data = val;
    newnode->next = top;     /* new node points to old top */
    top = newnode;           /* new node becomes the top   */
}

void pop()
{
    struct node *temp;
    if (top == NULL)
        printf("Stack Underflow\n");
    else
    {
        temp = top;
        printf("Deleted element: %d\n", temp->data);
        top = top->next;     /* move top to next node */
        free(temp);
    }
}

void display()
{
    struct node *ptr = top;
    if (ptr == NULL) { printf("Stack is empty\n"); return; }
    printf("Stack elements (top to bottom): ");
    while (ptr != NULL)
    {
        printf("%d ", ptr->data);
        ptr = ptr->next;
    }
    printf("\n");
}

int main()
{
    push(10); push(20); push(30);
    display();               /* 30 20 10 */
    pop();                   /* deletes 30 */
    display();               /* 20 10 */
    return 0;
}
Array stack: simple, fast, but fixed size → possible Overflow even when memory is free.
Linked list stack: dynamic size, no wasted space, but needs extra memory for pointers.

Step 0 — Master this FIRST : Precedence & Associativity

Before the algorithm, you must be 100% clear on two questions: (1) Which operator works first? (Precedence) and (2) If two operators are equally strong, who goes first? (Associativity)

1 Operator Precedence = Priority (who is stronger?)

Just like BODMAS in maths — multiplication happens before addition. Higher precedence = solved first.

OperatorPrecedence (power)AssociativityExample
^ (exponent / power)3 — highest 🥇Right → Left2 + 3 ^ 2 → first 3^2=9 → 2+9=11
* / (multiply, divide)2 — middle 🥈Left → Right2 + 3 * 4 → first 3*4=12 → 2+12=14
+ − (add, subtract)1 — lowest 🥉Left → Right2 + 3 − 1 → same power, go left to right
( inside the stack0 — weakest—Never popped by an operator; only ')' removes it

2 Associativity = Direction (same power, then who first?)

Associativity is needed ONLY when two operators have EQUAL precedence. It tells the direction of solving:

⬅ LEFT associative : + − * /

Solve from LEFT to RIGHT. The operator which came earlier (left side) is solved first.

  • 10 − 5 − 2 = (10 − 5) − 2 = 5 − 2 = 3 ✔
    NOT 10 − (5 − 2) = 7 ✘
  • 8 / 4 / 2 = (8 / 4) / 2 = 2 / 2 = 1 ✔
    NOT 8 / (4 / 2) = 4 ✘

➡ RIGHT associative : ^ only

Solve from RIGHT to LEFT. The operator which came later (right side) is solved first.

  • 2 ^ 3 ^ 2 = 2 ^ (3 ^ 2) = 2 ^ 9 = 512 ✔
    NOT (2 ^ 3) ^ 2 = 8 ^ 2 = 64 ✘
  • That is why postfix of A^B^C is ABC^^ (not AB^C^).

3 Same idea inside the STACK — Case 1 (≥ and Case 2 >

While converting, whenever you scan an operator, compare it with the operator sitting on the stack top:

Situation (compare with stack TOP)DecisionWhy? (from the algorithm)
Stack is empty, or top is (PUSHWhile-loop does not run. Push scanned.
Top has LOWER precedence than scannedPUSHNeither ≥ nor > is true → no pop. Push scanned.
Top has HIGHER precedence than scannedPOP → output, compare againBoth Case 1 (≥ and Case 2 > are true → pop.
EQUAL + LEFT associative (+ − * /)POP → output, then PUSHCase 1: ≥ is true when equal → pop.
EQUAL + RIGHT associative (^)PUSH only — NO pop!Case 2: > is false when equal → no pop.

Infix → Postfix : Complete Algorithm

Learn this algorithm by heart. The only hard part is the operator step — Case 1 uses ≥ (left-associative), Case 2 uses > (right-associative).

ALGORITHM — Infix to Postfix Conversion
1
Scan the infix expression from left to right.
2
For each scanned symbol:
  • If it is a left parenthesis (
    → PUSH it onto the stack.
  • If it is an operand (A–Z, a–z, 0–9)
    → Add it directly to the postfix output.
  • If it is a right parenthesis )
    → Repeatedly POP operators from the stack and add them to the postfix expression.
    → Stop when a left parenthesis ( is found and discard it (do not add it to the output).
  • If it is an operator (e.g., +, −, ×, ÷, ^)
    → While the stack is not empty, the top is not (, and:
    Case 1 Left-Associative Operator  (+ − * /)
    precedence(top of stack) ≥ precedence(scanned operator)
    Equal OR higher → POP
    Case 2 Right-Associative Operator  (^)
    precedence(top of stack) > precedence(scanned operator)
    Only strictly higher → POP  |  Equal → NO pop, just PUSH
    → Then POP that operator from the stack and add it to the postfix expression (repeat while condition is true).
    → Finally PUSH the scanned operator onto the stack.
3
After scanning the entire expression,
POP all remaining operators from the stack and add them to the postfix output.
4
End.
The output string is the postfix expression.

⭐ Important Points (must remember)

Case 1 = Left = ≥

For + − * / pop while TOP has equal or higher precedence. Memory: Left ≥

Case 2 = Right = >

For ^ pop while TOP has strictly higher precedence. Equal → only push. Memory: Right >

Operand never waits

Operands (A, B, 5…) go straight to output. Only operators and ( wait on the stack.

Always PUSH after while

After the Case 1 / Case 2 while-loop finishes, always push the scanned operator.

Brackets never in postfix

( is pushed; ) pops till (; then discard both. Postfix has no brackets.

End = empty the stack

When expression ends, pop everything left in the stack to the output.

Decision Tree — Operator Step
Scanned an OPERATOR? Check stack TOP: ├── Stack empty OR TOP is ( → PUSH scanned operator │ ├── LEFT-associative? (+ − * /) ├── Case 1: WHILE prec(TOP) ≥ prec(scanned) → POP TOP to output └── Then PUSH scanned │ └── RIGHT-associative? (^) ├── Case 2: WHILE prec(TOP) > prec(scanned) → POP TOP to output └── Then PUSH scanned Quick: Left → pop on equal OR higher (≥)  |  Right → pop only on higher (>)

Memory Tricks

  • Operand → output — never goes on the stack.
  • '(' → push, ')' → pop till '(' — then discard '('.
  • Case 1 (Left): ≥ — pop on equal or higher.
  • Case 2 (Right): > — pop only on higher. Equal → push.
  • Always push the scanned operator after the while-loop finishes.
  • End of scan → empty the whole stack into the output.
One-line formula: Left-associative → pop while TOP ≥ scanned. Right-associative → pop while TOP > scanned. Then always PUSH.

C Program — Infix to Postfix Conversion

infixtopostfix.c
#include <stdio.h>
#include <ctype.h>
#define MAX 100

char stack[MAX];
int top = -1;

void push(char c) {
    if (top < MAX - 1) {
        top = top + 1;
        stack[top] = c;
    }
}

char pop() {
    char ch = '\0';
    if (top != -1) {
        ch = stack[top];
        top = top - 1;
    }
    return ch;
}

char peek() {
    if (top != -1)
        return stack[top];
    return '\0';
}

int precedence(char op) {
    if (op == '^')
        return 3;
    else if (op == '*' || op == '/')
        return 2;
    else if (op == '+' || op == '-')
        return 1;
    else
        return 0;   /* for '(' */
}

int main() {
    char infix[MAX], postfix[MAX];
    int i = 0, j = 0;
    char ch;
    printf("Enter infix expression: ");
    gets(infix);

    while (infix[i] != '\0') {
        ch = infix[i];
        if (isalnum(ch)) {                 /* operand → output   */
            postfix[j] = ch;
            j = j + 1;
        } else if (ch == '(') {            /* '(' → push         */
            push(ch);
        } else if (ch == ')') {            /* ')' → pop till '(' */
            while (top != -1 && peek() != '(') {
                postfix[j] = pop();
                j = j + 1;
            }
            pop();                         /* remove '('         */
        } else {                           /* operator           */
            while (top != -1 && precedence(peek()) >= precedence(ch)) {
                postfix[j] = pop();
                j = j + 1;
            }
            push(ch);
        }
        i = i + 1;
    }
    while (top != -1) {                    /* pop the rest       */
        postfix[j] = pop();
        j = j + 1;
    }
    postfix[j] = '\0';
    printf("Postfix Expression: %s\n", postfix);
    return 0;
}
Example run: Input A+B*C-D/E*H → Output ABC*+DE/H*-

Evaluation of Postfix Expression (using Stack)

Good news: here you don't need precedence or associativity at all! Postfix already has the correct order built inside it. Only two rules: number → push, operator → pop two, compute, push back.

ALGORITHM — Postfix Evaluation
1
Create empty STACK. Scan postfix left → right.
2
If symbol is a NUMBER
→ PUSH it onto the stack.
3
If symbol is an OPERATOR (+ − * / ^)
3a. b = POP()  ← first pop = SECOND operand
3b. a = POP()  ← second pop = FIRST operand
3c. result = a operator b  (a first! b second!)
3d. PUSH(result) back onto the stack
4
Repeat steps 2–3 until the expression ends.
5
POP() → single value left = FINAL ANSWER

⚠ Most important!

Order: first pop = b, second pop = a. Result = a op b, NOT b op a.

Mini dry run : 8 2 /

SymbolActionStack
8number → push 88
2number → push 28, 2
/b=pop()=2, a=pop()=8 → a/b = 8/2 = 4 → push 44
Most common mistake! First popped value is b (right side), second popped is a (left side). Answer = a − b / a ÷ b, NOT b − a. Here 8/2 = 4 ✔, not 2/8 ✘.

Mini dry run : 2 3 4 * +  (infix: 2 + 3 * 4)

SymbolActionStack
2push 22
3push 32, 3
4push 42, 3, 4
*b=4, a=3 → 3*4 = 12 → push2, 12
+b=12, a=2 → 2+12 = 14 → push14

Answer = 14 — exactly what BODMAS gives for 2 + 3 * 4. The stack did it automatically!

Why postfix? No precedence rules and no brackets are needed — the computer just scans once, left to right. That is why compilers convert infix to postfix first!

C Program — Postfix Expression Evaluation

postfixeval.c
#include <stdio.h>
#include <ctype.h>
#define MAX 100

int stack[MAX];
int top = -1;

void push(int n) {
    if (top < MAX - 1) {
        top = top + 1;
        stack[top] = n;
    }
}

int pop() {
    int x = 0;
    if (top != -1) {
        x = stack[top];
        top = top - 1;
    }
    return x;
}

int main() {
    char postfix[MAX];
    int i = 0, a, b, result = 0, j;
    printf("Enter postfix expression: ");
    gets(postfix);

    while (postfix[i] != '\0') {
        char ch = postfix[i];
        if (isdigit(ch)) {
            push(ch - '0');          /* char digit → int   */
        } else {
            b = pop();               /* first pop  = b     */
            a = pop();               /* second pop = a     */
            if (ch == '+') {
                result = a + b;
            } else if (ch == '-') {
                result = a - b;
            } else if (ch == '*') {
                result = a * b;
            } else if (ch == '/') {
                result = a / b;
            } else if (ch == '^') {  /* a to the power b   */
                result = 1;
                for (j = 0; j < b; j++) {
                    result = result * a;
                }
            }
            push(result);
        }
        i = i + 1;
    }
    printf("Result: %d\n", pop());
    return 0;
}
Example run: Input 6523+8*+3+* → Result 288

Bonus — Prefix Expression Evaluation (scan RIGHT to LEFT)

Prefix is evaluated the same way, but we scan from right to left, and after popping: first popped = a, second popped = b.

prefixeval.c
#include <stdio.h>
#include <string.h>
#include <ctype.h>
#define MAX 100

int stack[MAX];
int top = -1;

void push(int n) {
    if (top < MAX - 1) {
        top = top + 1;
        stack[top] = n;
    }
}

int pop() {
    int x = 0;
    if (top != -1) {
        x = stack[top];
        top = top - 1;
    }
    return x;
}

int main() {
    char prefix[MAX];
    int len, i, a, b, result = 0, j;
    printf("Enter prefix expression: ");
    gets(prefix);
    len = strlen(prefix);

    i = len - 1;                     /* start from the END */
    while (i >= 0) {
        char ch = prefix[i];
        if (isdigit(ch)) {
            push(ch - '0');
        } else {
            a = pop();               /* first pop  = a     */
            b = pop();               /* second pop = b     */
            if (ch == '+')      result = a + b;
            else if (ch == '-') result = a - b;
            else if (ch == '*') result = a * b;
            else if (ch == '/') result = a / b;
            else if (ch == '^') {
                result = 1;
                for (j = 0; j < b; j++)
                    result = result * a;
            }
            push(result);
        }
        i = i - 1;
    }
    printf("Result: %d\n", pop());
    return 0;
}

What is a Data Structure?

A Data Structure is a way of organizing and storing data in memory so that it can be used efficiently.

Examples: Array, Linked List, Stack, Queue, Tree, Graph.

Need of Data Structures (exam points from Unit I notes)

As applications become complex and data grows, these problems appear:

  • Processor speed: Billions of files → CPU may fail to handle data fast enough without good organization.
  • Data Search: Inventory of 106 items — sequential search every time is too slow.
  • Multiple requests: Thousands of users searching at once can overload a server.
Solution: Organize data as a data structure so that we need not search all items — required data can be found quickly.

Advantages

  • Efficiency — correct DS makes search/insert/delete faster (e.g. BST / hash vs plain array)
  • Reusability — implement once, reuse in libraries / other programs
  • Abstraction — ADT interface hides implementation details from the user
  • Better organization — store and retrieve user data as fast as possible
Exam tip (2–5 marks): Define DS + write Need (3 problems) + Advantages (Efficiency, Reusability, Abstraction).

Classification of Data Structures

Three common ways asked in exams.

1 Primitive vs Non-Primitive

  • Primitive: Basic built-in types provided by the language. Store one value. Examples: int, float, char, boolean.
  • Non-Primitive: Derived / user-defined structures that store a collection of values. Examples: Array, Linked List, Stack, Queue, Tree, Graph.

2 Static vs Dynamic

  • Static: Size is fixed at compile time / creation. Example: Array, array-based stack.
  • Dynamic: Size can grow or shrink at run time. Example: Linked List, linked stack.

3 Linear vs Non-Linear

  • Linear: Elements form a sequence (one after another). Each element has at most one predecessor and one successor. Examples: Array, Linked List, Stack, Queue.
  • Non-Linear: Elements form a hierarchy or network. One element can connect to many. Examples: Tree, Graph, Heap.
Linear: A → B → C → D (single path)
Non-Linear: Tree / Graph (many paths / levels)
Exam tip: “Distinguish between Linear and Non-Linear DS with examples” is a very common 5–8 mark question.

Abstract Data Type (ADT)

An ADT is a mathematical model of a data type defined by:

  • the data it stores, and
  • the operations allowed on that data,

without specifying how it is implemented in memory.

Example: Stack ADT = LIFO collection + operations push, pop, peek, isEmpty, isFull. Implementation may use array or linked list — the ADT stays the same.
Exam tip: “ADT hides implementation details and shows only the interface (operations).”

Stack — Definition & LIFO

A Stack is a linear data structure in which insertion and deletion are allowed only at one end called the TOP.

It follows the LIFO principle — Last In, First Out. The last element pushed is the first one popped.

Real-life examples

  • Pile of plates — top plate is taken first
  • Stack of books
  • Bangles on a wrist
  • Undo history in a text editor
  • Browser Back button history

Overflow & Underflow

Overflow: Trying to push when the stack is already full (top == MAX-1 for array stack).
Underflow: Trying to pop / peek when the stack is empty (top == -1).
Exam tip: Always mention TOP, LIFO, and draw a small diagram with 3–4 elements for full marks.

Stack Operations (short algorithms)

1. Push (insert at TOP)

  • If top == MAX - 1 → report Overflow and stop
  • Else top = top + 1
  • stack[top] = x

2. Pop (delete from TOP)

  • If top == -1 → report Underflow and stop
  • Else x = stack[top]
  • top = top - 1
  • Return / print x

3. Peek / Top (read TOP without deleting)

  • If top == -1 → stack empty
  • Else return stack[top] (do not change top)

4. Display

  • If top == -1 → print “Stack empty”
  • Else print from i = top down to 0 (TOP printed first)
Remember (array stack)
push → top = top + 1; stack[top] = x;
pop  → x = stack[top]; top = top - 1;
empty when top == -1; full when top == MAX-1;

Expressions — Infix, Postfix, Prefix

TypeFormExample for A + B * C
InfixOperator between operandsA + B * C
Postfix (Reverse Polish)Operator after operandsA B C * + → ABC*+
Prefix (Polish)Operator before operands+ A * B C → +A*BC
Why postfix? No brackets and no precedence checks during evaluation — ideal for computers / compilers.

Infix to Postfix — Conversion Rules (brief)

Scan infix left → right. Use a stack for operators and parentheses.

  • Operand (A, B, 1, 2…) → write directly to output
  • ( → push onto stack
  • ) → pop and write until matching ( is removed
  • Operator → compare precedence / associativity with TOP, then push
  • At end → pop and write all remaining operators
Case 1 — Left associative (+ − * /)
Pop while TOP precedence ≥ scanned operator precedence, then push scanned.
Case 2 — Right associative (^)
Pop while TOP precedence > scanned operator precedence, then push scanned.
One-line formula: Left → pop while TOP ≥ scanned. Right → pop while TOP > scanned. Then always push.
Exam tip: Show a step table: Scanned | Stack | Output for full marks.

Postfix Evaluation — Rules

Scan postfix left → right. No precedence needed.

  • If operand → push onto stack
  • If operator:
    • b = first pop (right operand)
    • a = second pop (left operand)
    • Compute a □ b and push result back
  • Final answer = only value left in stack
Most common mistake: For - and /, answer is a − b / a ÷ b, not b − a. Example: stack has 8 then 2, operator / → pop b=2, pop a=8 → 8/2 = 4.
Exam tip: Always label pops as b then a in your answer sheet.

Exam Short Notes (write these as-is)

Define Data Structure

Group of data elements that provides an efficient way of storing and organizing data so it can be used efficiently. Examples: Array, Linked List, Stack, Queue.

Define Stack

Linear list where insertion and deletion happen only at one end called TOP. Follows LIFO (Last In, First Out).

Overflow / Underflow

Overflow: push when stack is full (top == size−1).
Underflow: pop when stack is empty (top == −1).

Left ≥  |  Right >

Infix→Postfix operator step:
Left (+ − * /): pop while TOP ≥ scanned.
Right (^): pop while TOP > scanned.

Postfix eval order

On operator: b = first pop, a = second pop, push a op b. Example 8 2 / → 4 (not 0).

ADT one-liner

Logical description of data + allowed operations without saying how it is implemented (information hiding).
