1.1 Data Structure — Definition

Definition: Data Structure can be defined as the group of data elements which provides an efficient way of storing and organizing data in the computer so that it can be used efficiently.
  • Examples: Arrays, Linked List, Stack, Queue, Tree, Graph, etc.
  • Data Structures are widely used in almost every aspect of Computer Science — Operating System, Compiler Design, Artificial Intelligence, Graphics and many more.
  • Data Structures are the main part of many computer science algorithms as they enable programmers to handle data in an efficient way.
  • It plays a vital role in enhancing the performance of software or a program — the main function of software is to store and retrieve user data as fast as possible.

1.2 Basic Terminology

Data structures are the building blocks of any program or software. Choosing the appropriate data structure for a program is the most difficult task for a programmer. Following terminology is used as far as data structures are concerned:

TermMeaning
DataData can be defined as an elementary value or the collection of values. Example: student's name and its id are the data about the student.
Group ItemsData items which have subordinate data items are called Group item. Example: name of a student can have first name and last name.
RecordRecord can be defined as the collection of various data items. Example: student entity — name, address, course and marks grouped together form the record for the student.
FileA File is a collection of various records of one type of entity. Example: if there are 60 employees in the class, then there will be 60 records in the related file where each record contains data about each employee.
EntityAn entity represents the class of certain objects. It contains various attributes. Each attribute represents a particular property of that entity.
AttributeAttribute represents the particular property of an entity.
FieldField is a single elementary unit of information representing the attribute of an entity.
Chain: Entity → Attributes → Fields → Record → File

1.3 Need of Data Structures

As applications are getting complex and amount of data is increasing day by day, the following problems may arise:

  1. Processor speed: To handle very large amount of data, high speed processing is required. But as data grows day by day to billions of files per entity, processor may fail to deal with that much amount of unorganized data.
  2. Data Search: Consider an inventory size of 106 items in a store. If application needs to search a particular item, it must traverse 106 items every time — results in slowing down the search process.
  3. Multiple requests: If thousands of users search data simultaneously on a web server, there are chances that a very large server can fail during that process.
Solution: In order to solve the above problems, data structures are used. Data is organized to form a data structure in such a way that all items are not required to be searched — required data can be searched instantly.

1.4 Advantages of Data Structures

  • Efficiency: Efficiency of a program depends upon the choice of data structures. Example: if we organize data in an array, we must search sequentially element by element — not very efficient. Better data structures: ordered array, binary search tree, hash tables.
  • Reusability: Data structures are reusable — once implemented, can be used at any other place. Implementation can be compiled into libraries used by different clients.
  • Abstraction: Data structure is specified by the ADT which provides a level of abstraction. Client program uses data structure through interface only, without getting into implementation details.

2. Types of Data Structures

Syllabus types: Static, Dynamic, Primitive, Non-Primitive, Linear, Non-Linear — see diagram and distinguish tables below.

Note: Under Linear → Static = Array; Dynamic = Linked List, Stack, Queue. Under Non Linear → Tree, Graph. Stack & Queue can be implemented both ways (array = static, linked list = dynamic).

2.1 Linear Data Structures

Definition: A data structure is called linear if all of its elements are arranged in the linear order. In linear data structures, elements are stored in non-hierarchical way where each element has successors and predecessors except the first and last element.

If a data structure organizes data in sequential order, it is called a Linear Data Structure.

Examples: Arrays, List (Linked List), Stack, Queue

Arrays

  • An array is a collection of similar type of data items; each data item is called an element of the array.
  • Data type of element may be any valid type: char, int, float or double.
  • Elements share the same variable name but each carries a different index number (subscript).
  • Array can be one dimensional, two dimensional or multidimensional.
  • Individual elements: age[0], age[1], age[2], ... age[98], age[99]

Linked List

  • Linked list is a linear data structure used to maintain a list in memory.
  • Collection of nodes stored at non-contiguous memory locations.
  • Each node contains a pointer to its adjacent node.

Stack

  • Stack is a linear list in which insertion and deletions are allowed only at one end called top.
  • Stack is an Abstract Data Type (ADT); can be implemented in most programming languages.
  • Named stack because it behaves like real-world stack — piles of plates, deck of cards, etc.

Queue

  • Queue is a linear list — elements inserted only at one end called rear and deleted only at other end called front.
  • Abstract data structure, similar to stack.
  • Opened at both ends — follows FIFO (First-In-First-Out) methodology.

2.2 Non-Linear Data Structures

Definition: This data structure does not form a sequence — each item is connected with two or more other items in non-linear arrangement. Data elements are not arranged in sequential structure.

If data is organized in random order (not sequential), it is Non-Linear Data Structure.

Examples: Tree, Graph, Dictionaries, Heaps, Tries, etc.

Trees

  • Trees are multilevel data structures with hierarchical relationship among elements known as nodes.
  • Bottommost nodes = leaf nodes; topmost node = root node.
  • Each node contains pointers to adjacent nodes.
  • Based on parent-child relationship.
  • Each node can have more than one child (except leaves); each node has at most one parent (except root).
  • Many categories — binary tree, BST, AVL (discussed later in course).

Graphs

  • Pictorial representation of set of elements (vertices) connected by links known as edges.
  • Graph is different from tree: graph can have cycle while tree cannot have cycle.

Way 1 By Nature

  • Primitive — int, float, char, boolean, pointer
  • Non-Primitive — Array, List, Stack, Queue, Tree, Graph

Way 2 By Arrangement

  • Linear — Array, Linked List, Stack, Queue
  • Non-Linear — Tree, Graph, Heap, Dictionary

Way 3 By Memory

  • Static — Array (fixed at compile time)
  • Dynamic — Linked List, dynamic Stack / Queue

3. Stack — Definition, LIFO, Overflow & Underflow

A Stack is a linear data structure. A stack is a list of elements in which an element may be inserted or deleted only at one end, called the top of the stack.

Stack principle is LIFO (Last In, First Out). The element inserted last on to the stack is deleted first from the stack. As the items can be added or removed only from the top, the last item to be added to a stack is the first item to be removed.

Real-life Examples of Stack

  • Piles of plates — top plate removed first
  • Deck of cards
  • Stack of books, bangles on a wrist
  • Undo (Ctrl+Z) in text editor
  • Browser Back button history
  • Function call stack in recursion

Operations on Stack

The two basic operations associated with stacks are:

  1. Push
  2. Pop

While performing push and pop operations the following tests must be conducted on the stack:

  1. Stack is empty or not
  2. Stack is full or not

Push

Push operation is used to add new elements into the stack. At the time of addition first check the stack is full or not. If the stack is full it generates an error message "stack overflow".

Pop

Pop operation is used to delete elements from the stack. At the time of deletion first check the stack is empty or not. If the stack is empty it generates an error message "stack underflow".

Key points: All insertions and deletions take place at the same end, so the last element added to the stack will be the first element removed. When a stack is created, the stack base remains fixed while the stack top changes as elements are added and removed. The most accessible element is the top and the least accessible element is the bottom of the stack.

Overflow & Underflow

Stack Overflow: Trying to push when stack is full (top == MAX-1 or top == size-1 for array).
Stack Underflow: Trying to pop / peek when stack is empty (top == -1).

Algorithm — push()

Step 1: START
Step 2: if top >= size-1 then
            write "Stack is Overflow"
Step 3: otherwise
        3.1: read data value 'x'
        3.2: top = top + 1
        3.3: stack[top] = x
Step 4: END

Algorithm — pop()

Step 1: START
Step 2: if top == -1 then
            write "Stack is Underflow"
Step 3: otherwise
        3.1: print "deleted element" stack[top]
        3.2: top = top - 1
Step 4: END

Algorithm — peek()

Step 1: START
Step 2: if top == -1 then write "Stack is Empty"
Step 3: otherwise print "Top element =" stack[top]  (do NOT change top)
Step 4: END

Algorithm — display()

Step 1: START
Step 2: if top == -1 then write "Stack is Empty"
Step 3: otherwise
        3.1: print "Elements are:"
        3.2: for i = top down to 0  →  print stack[i]
Step 4: END
Remember (array stack):
  push → top = top + 1; stack[top] = x;
  pop  → x = stack[top]; top = top - 1;
  empty when top == -1;  full when top == MAX-1;

8. Conversion of Polish Notations — Infix to Postfix

Scan infix left → right. Use a stack for operators / parentheses. Write postfix to output.

Left associative (+ − * /): pop while precedence(TOP) ≥ precedence(scanned)
Right associative (^): pop while precedence(TOP) > precedence(scanned) — equal ^ does NOT pop

Complete Algorithm

  1. Initialize empty stack and empty output string.
  2. Scan the infix expression from left to right, one symbol at a time.
  3. If symbol is an operand (A–Z / 0–9) → append it to output.
  4. If symbol is ( → PUSH onto stack.
  5. If symbol is ) → POP and append to output until ( is popped (discard ().
  6. If symbol is an operator:
    • Case 1 — Left associative (+ − * /): while stack not empty and TOP is operator and precedence(TOP) ≥ precedence(scanned) → POP to output. Then PUSH scanned.
    • Case 2 — Right associative (^): while stack not empty and TOP is operator and precedence(TOP) > precedence(scanned) → POP to output. Then PUSH scanned. (Equal ^ does NOT pop.)
  7. After whole expression is scanned → POP and append all remaining operators from stack.
  8. Output string is the postfix expression.

Decision Tree (Quick Reference)

Is scanned operator precedence > stack top?
├── YES → PUSH directly
└── NO → Is precedence equal?
    ├── YES → Is operator right associative?
    │   ├── YES (^) → PUSH (Cases 7, 8)
    │   └── NO (Left) → POP then PUSH (Cases 5, 6)
    └── NO → POP then check again (Cases 2, 3, 4)
Memory: Higher wins | Left pops equal | Right stacks equal

9. Evaluation of Postfix Expressions

Postfix expression is evaluated easily by using a stack. Scan the expression from left to right. No operator precedence rules are needed in postfix.

Key idea: When a number is seen → PUSH it onto the stack. When an operator is seen → POP two operands, apply the operator, and PUSH the result back. After complete scan, the final answer is the only value left in the stack.

Algorithm — Evaluation of Postfix Expression

Step 1: START
Step 2: Create an empty stack
Step 3: Scan the postfix expression from LEFT to RIGHT, one symbol at a time
Step 4: If scanned symbol is an OPERAND (number)
            PUSH it onto the stack
Step 5: If scanned symbol is an OPERATOR
            b = POP()          /* first pop  = RIGHT operand */
            a = POP()          /* second pop = LEFT operand  */
            result = a operator b
            PUSH result onto stack
Step 6: Repeat Step 3 until end of expression
Step 7: POP the stack — this is the FINAL ANSWER
Step 8: END
Exam rule (very important): For − and /, compute a − b and a ÷ b where a = second pop (left) and b = first pop (right). Example: stack [8, 2], operator / → a=8, b=2 → answer = 4 (not 0).

① Rules — Precedence & Associativity (optional reference)

Step 0 — Master this FIRST : Precedence & Associativity

Before the algorithm, you must be 100% clear on two questions: (1) Which operator works first? (Precedence) and (2) If two operators are equally strong, who goes first? (Associativity)

1 Operator Precedence = Priority (who is stronger?)

Just like BODMAS in maths — multiplication happens before addition. Higher precedence = solved first.

OperatorPrecedence (power)AssociativityExample
^ (exponent / power)3 — highest 🥇Right → Left2 + 3 ^ 2 → first 3^2=9 → 2+9=11
* / (multiply, divide)2 — middle 🥈Left → Right2 + 3 * 4 → first 3*4=12 → 2+12=14
+ − (add, subtract)1 — lowest 🥉Left → Right2 + 3 − 1 → same power, go left to right
( inside the stack0 — weakest—Never popped by an operator; only ')' removes it

2 Associativity = Direction (same power, then who first?)

Associativity is needed ONLY when two operators have EQUAL precedence. It tells the direction of solving:

⬅ LEFT associative : + − * /

Solve from LEFT to RIGHT. The operator which came earlier (left side) is solved first.

  • 10 − 5 − 2 = (10 − 5) − 2 = 5 − 2 = 3 ✔
    NOT 10 − (5 − 2) = 7 ✘
  • 8 / 4 / 2 = (8 / 4) / 2 = 2 / 2 = 1 ✔
    NOT 8 / (4 / 2) = 4 ✘

➡ RIGHT associative : ^ only

Solve from RIGHT to LEFT. The operator which came later (right side) is solved first.

  • 2 ^ 3 ^ 2 = 2 ^ (3 ^ 2) = 2 ^ 9 = 512 ✔
    NOT (2 ^ 3) ^ 2 = 8 ^ 2 = 64 ✘
  • That is why postfix of A^B^C is ABC^^ (not AB^C^).

3 Same idea inside the STACK — Case 1 (≥ and Case 2 >

While converting, whenever you scan an operator, compare it with the operator sitting on the stack top:

Situation (compare with stack TOP)DecisionWhy? (from the algorithm)
Stack is empty, or top is (PUSHWhile-loop does not run. Push scanned.
Top has LOWER precedence than scannedPUSHNeither ≥ nor > is true → no pop. Push scanned.
Top has HIGHER precedence than scannedPOP → output, compare againBoth Case 1 (≥ and Case 2 > are true → pop.
EQUAL + LEFT associative (+ − * /)POP → output, then PUSHCase 1: ≥ is true when equal → pop.
EQUAL + RIGHT associative (^)PUSH only — NO pop!Case 2: > is false when equal → no pop.

Infix → Postfix : Complete Algorithm

Learn this algorithm by heart. The only hard part is the operator step — Case 1 uses ≥ (left-associative), Case 2 uses > (right-associative).

ALGORITHM — Infix to Postfix Conversion
1
Scan the infix expression from left to right.
2
For each scanned symbol:
  • If it is a left parenthesis (
    → PUSH it onto the stack.
  • If it is an operand (A–Z, a–z, 0–9)
    → Add it directly to the postfix output.
  • If it is a right parenthesis )
    → Repeatedly POP operators from the stack and add them to the postfix expression.
    → Stop when a left parenthesis ( is found and discard it (do not add it to the output).
  • If it is an operator (e.g., +, −, ×, ÷, ^)
    → While the stack is not empty, the top is not (, and:
    Case 1 Left-Associative Operator  (+ − * /)
    precedence(top of stack) ≥ precedence(scanned operator)
    Equal OR higher → POP
    Case 2 Right-Associative Operator  (^)
    precedence(top of stack) > precedence(scanned operator)
    Only strictly higher → POP  |  Equal → NO pop, just PUSH
    → Then POP that operator from the stack and add it to the postfix expression (repeat while condition is true).
    → Finally PUSH the scanned operator onto the stack.
3
After scanning the entire expression,
POP all remaining operators from the stack and add them to the postfix output.
4
End.
The output string is the postfix expression.

C Program — Infix to Postfix Conversion

infixtopostfix.c
#include <stdio.h>
#include <ctype.h>
#define MAX 100

char stack[MAX];
int top = -1;

void push(char c) {
    if (top < MAX - 1) {
        top = top + 1;
        stack[top] = c;
    }
}

char pop() {
    char ch = '\0';
    if (top != -1) {
        ch = stack[top];
        top = top - 1;
    }
    return ch;
}

char peek() {
    if (top != -1)
        return stack[top];
    return '\0';
}

int precedence(char op) {
    if (op == '^')
        return 3;
    else if (op == '*' || op == '/')
        return 2;
    else if (op == '+' || op == '-')
        return 1;
    else
        return 0;   /* for '(' */
}

int main() {
    char infix[MAX], postfix[MAX];
    int i = 0, j = 0;
    char ch;
    printf("Enter infix expression: ");
    gets(infix);

    while (infix[i] != '\0') {
        ch = infix[i];
        if (isalnum(ch)) {                 /* operand → output   */
            postfix[j] = ch;
            j = j + 1;
        } else if (ch == '(') {            /* '(' → push         */
            push(ch);
        } else if (ch == ')') {            /* ')' → pop till '(' */
            while (top != -1 && peek() != '(') {
                postfix[j] = pop();
                j = j + 1;
            }
            pop();                         /* remove '('         */
        } else {                           /* operator           */
            if (ch == '^') {               /* Case 2: ^ right-assoc — use > only */
                while (top != -1 && peek() != '(' &&
                       precedence(peek()) > precedence(ch)) {
                    postfix[j] = pop();
                    j = j + 1;
                }
            } else {                       /* Case 1: + - * / left-assoc — use >= */
                while (top != -1 && peek() != '(' &&
                       precedence(peek()) >= precedence(ch)) {
                    postfix[j] = pop();
                    j = j + 1;
                }
            }
            push(ch);
        }
        i = i + 1;
    }
    while (top != -1) {                    /* pop the rest       */
        postfix[j] = pop();
        j = j + 1;
    }
    postfix[j] = '\0';
    printf("Postfix Expression: %s\n", postfix);
    return 0;
}
Example run: Input A+B*C-D/E*H → Output ABC*+DE/H*-
A^B^C → ABC^^ (stack TOP ^ + scanned ^ → Case 2: 3 > 3 false → NO pop, only PUSH)

Evaluation of Postfix Expression (using Stack)

Good news: here you don't need precedence or associativity at all! Postfix already has the correct order built inside it. Only two rules: number → push, operator → pop two, compute, push back.

ALGORITHM — Postfix Evaluation
1
Create empty STACK. Scan postfix left → right.
2
If symbol is a NUMBER
→ PUSH it onto the stack.
3
If symbol is an OPERATOR (+ − * / ^)
3a. b = POP()  ← first pop = SECOND operand
3b. a = POP()  ← second pop = FIRST operand
3c. result = a operator b  (a first! b second!)
3d. PUSH(result) back onto the stack
4
Repeat steps 2–3 until the expression ends.
5
POP() → single value left = FINAL ANSWER

⚠ Most important!

Order: first pop = b, second pop = a. Result = a op b, NOT b op a.

Mini dry run : 8 2 /

SymbolActionStack
8number → push 88
2number → push 28, 2
/b=pop()=2, a=pop()=8 → a/b = 8/2 = 4 → push 44
Most common mistake! First popped value is b (right side), second popped is a (left side). Answer = a − b / a ÷ b, NOT b − a. Here 8/2 = 4 ✔, not 2/8 ✘.

Mini dry run : 2 3 4 * +  (infix: 2 + 3 * 4)

SymbolActionStack
2push 22
3push 32, 3
4push 42, 3, 4
*b=4, a=3 → 3*4 = 12 → push2, 12
+b=12, a=2 → 2+12 = 14 → push14

Answer = 14 — exactly what BODMAS gives for 2 + 3 * 4. The stack did it automatically!

Why postfix? No precedence rules and no brackets are needed — the computer just scans once, left to right. That is why compilers convert infix to postfix first!

C Program — Postfix Expression Evaluation

postfixeval.c
#include <stdio.h>
#include <ctype.h>
#define MAX 100

int stack[MAX];
int top = -1;

void push(int n) {
    if (top < MAX - 1) {
        top = top + 1;
        stack[top] = n;
    }
}

int pop() {
    int x = 0;
    if (top != -1) {
        x = stack[top];
        top = top - 1;
    }
    return x;
}

int main() {
    char postfix[MAX];
    int i = 0, a, b, result = 0, j;
    printf("Enter postfix expression: ");
    gets(postfix);

    while (postfix[i] != '\0') {
        char ch = postfix[i];
        if (isdigit(ch)) {
            push(ch - '0');          /* char digit → int   */
        } else {
            b = pop();               /* first pop  = b     */
            a = pop();               /* second pop = a     */
            if (ch == '+') {
                result = a + b;
            } else if (ch == '-') {
                result = a - b;
            } else if (ch == '*') {
                result = a * b;
            } else if (ch == '/') {
                result = a / b;
            } else if (ch == '^') {  /* a to the power b   */
                result = 1;
                for (j = 0; j < b; j++) {
                    result = result * a;
                }
            }
            push(result);
        }
        i = i + 1;
    }
    printf("Result: %d\n", pop());
    return 0;
}
Example run: Input 6523+8*+3+* → Result 288

Bonus — Prefix Expression Evaluation (scan RIGHT to LEFT)

Prefix is evaluated the same way, but we scan from right to left, and after popping: first popped = a, second popped = b.

prefixeval.c
#include <stdio.h>
#include <string.h>
#include <ctype.h>
#define MAX 100

int stack[MAX];
int top = -1;

void push(int n) {
    if (top < MAX - 1) {
        top = top + 1;
        stack[top] = n;
    }
}

int pop() {
    int x = 0;
    if (top != -1) {
        x = stack[top];
        top = top - 1;
    }
    return x;
}

int main() {
    char prefix[MAX];
    int len, i, a, b, result = 0, j;
    printf("Enter prefix expression: ");
    gets(prefix);
    len = strlen(prefix);

    i = len - 1;                     /* start from the END */
    while (i >= 0) {
        char ch = prefix[i];
        if (isdigit(ch)) {
            push(ch - '0');
        } else {
            a = pop();               /* first pop  = a     */
            b = pop();               /* second pop = b     */
            if (ch == '+')      result = a + b;
            else if (ch == '-') result = a - b;
            else if (ch == '*') result = a * b;
            else if (ch == '/') result = a / b;
            else if (ch == '^') {
                result = 1;
                for (j = 0; j < b; j++)
                    result = result * a;
            }
            push(result);
        }
        i = i - 1;
    }
    printf("Result: %d\n", pop());
    return 0;
}
